# 全部基础资料导入

范围延续数据导入导出页面的七类资料，并补充用户依赖的部门树，共八类。不是数据库备份恢复。

## 实体关系

| 实体 | 实际关联 | 导入规则 |
| --- | --- | --- |
| Department | superior 关联上级部门 | 部门编码唯一，上级编码可引用同文件或已有部门；按层级创建，拒绝循环和缺失上级 |
| Position | 独立岗位字典 | 岗位编码唯一，先于用户创建 |
| User | department、position 为实体关联；roles 为角色集合 | 使用部门编码和岗位编码解析新生成的 ID；角色沿用创建用户服务的分配策略 |
| ParkingOwner | dept 是文本，不是部门外键 | 卡号唯一；数量从实际车位、车牌统计，余额默认 0 |
| ParkingPlate | ownerId 保存车主 ID，owner 保存姓名副本 | 通过唯一车主卡号查找实际 ID，同时填写姓名 |
| ParkingSpot | owner 仅保存车主姓名 | 全部导入时要求姓名唯一匹配车主，拒绝重名或不存在的关联 |
| Device | 当前导入字段没有实体依赖 | 设备编号唯一 |
| GatePerson | dept 为文本；审核和同步有流程状态 | 人员编号、身份证号唯一，新记录为待审核、未同步 |

仓库还有另一套 CarMasterInfo 车辆主档，关联部门、车辆类型、车牌类型及内嵌车卡/车位明细，不能当作 ParkingOwner/ParkingPlate 的别名。
AccessControl 关联部门及门禁类型并带审批、同步状态；AccessRecord 关联车辆类型且承载通行事实；GateDeleteRequest 的 personId 指向门禁人员。
这些实体、角色权限配置、文件和审计记录不在本次基础资料样表中。

## 使用

1. 在数据导入导出页面点击“下载全部导入样表”（GET /api/excel/all/template）。
2. 修改示例行，包括用户名、密码、邮箱和业务编码。示例不是注释，上传后会实际创建。
3. 保留八个资料工作表及表头；不需要的数据删除行即可。说明工作表不参与导入。
4. 点击“导入全部数据”（POST /api/excel/all/import，multipart 字段 file）。

部门编码、岗位编码、车主卡号可以引用当前文件新记录，也可以引用系统已有记录；不应同时填写编码和数据库 ID。
部门、岗位、卡号、设备编号等重复时拒绝新增，不覆盖已有数据。
全文件使用同一数据库事务，后续工作表校验失败时回滚此前创建的数据。返回总条数及各工作表条数。
导入要求管理员角色及八类资料对应的创建/管理权限，用户角色仍由现有角色分配策略校验。

日期使用 ISO 日期，如 2026-09-09；车主、车位、车牌状态用 0/1。门禁审批、同步由后续业务流程完成。
“导出全部数据”是阅读用报表，缺少密码等必填信息，不能直接用作本样表。
